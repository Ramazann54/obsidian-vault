Тема моей выпускной квалификационной работы — разработка мобильного приложения для управления интеллектуальными приборами учета.

В работе рассматривается мобильное приложение, которое позволяет пользователю взаимодействовать с прибором учета через серверное API.

**Слайд 2. Актуальность темы**

**Интеллектуальные приборы учёта электроэнергии (ИПУЭ)** — это современные устройства, которые позволяют измерять, фиксировать, передавать и анализировать данные о потреблении электроэнергии в режиме реального времени.

Актуальность связана с развитием интеллектуальных систем учета электроэнергии. В связи с чем передача показаний вручную (через квитанции, телефонные звонки или контролеров) уходит из обихода потребителей электроэнергии. Сейчас приборы учета могут передавать данные автоматически, а пользователю важно иметь удобный доступ к этим данным через цифровой сервис.

Согласно Федеральному закону № 522-ФЗ приборы учета электрической энергии, допускаемые в эксплуатацию, должны быть интеллектуальными. Поэтому возрастает потребность в программном обеспечении, которое дает пользователю доступ к данным прибора учета.

---

**Слайд 3. Цель и задачи работы**

Целью работы является разработка мобильного приложения для управления интеллектуальными приборами учета. В данном случае под управлением понимается удобный способ контролировать расход электроэнергии и работать с данными прибора учета, то есть передавать показания.

Для достижения цели были проанализированы требования пользователя, сформулированы функциональные требования, спроектирована архитектура приложения, реализованы основные экраны и настроено взаимодействие с серверной частью.

На основе этого были выделены основные функции приложения: отображение текущих показаний, добавление прибора учета, передача показаний, архив, диагностика и отображение информации об устройстве. Эти функции затем легли в основу проектирования и реализации приложения.

**Слайд 5. Стек технологий**

Мобильное приложение разработано для платформы Android на языке Kotlin. Пользовательский интерфейс реализован с помощью XML-разметки и компонентов AndroidX.

Архитектура приложения построена на основе MVP. В рамках этого подхода View отвечает за отображение интерфейса, Presenter обрабатывает действия пользователя, а Model содержит данные, сервисы и классы серверного взаимодействия.

Для обмена с серверной частью используется REST API. Серверные запросы выполняются через HttpURLConnection, а полученные JSON-ответы преобразуются в объекты приложения с помощью библиотеки Gson.

Так как сетевые операции не должны блокировать интерфейс, асинхронная работа реализована с использованием Kotlin Coroutines. Сервис создает объект запроса, передает в него CoroutineScope, а результат возвращается в Presenter через listener.

В качестве среды разработки использовалась Android Studio, сборка проекта выполнялась с помощью Gradle, а для контроля версий применялся Git.

---

**Слайд 6. Архитектура приложения**

В приложении используется архитектурный подход MVP. Слой View отвечает за отображение интерфейса и получение действий пользователя. К нему относятся Activity, Fragment и Dialog’и. Presenter содержит основную логику обработки действий пользователя: проверяет данные, обращается к сервисам и передает результат обратно во View.

Слой Model содержит модели данных, сервисы, а также классы серверных запросов и ответов. Presenter не обращается к серверным запросам и работе с сетью напрямую, а вызывает соответствующий метод сервиса. Результат возвращается через listener.

---

**Слайд 7. Пользовательские сценарии**

Основные пользовательские сценарии были спроектированы через структуру экранов. Первый сценарий — регистрация пользователя и переход на главный экран, где при отсутствии приборов отображается сообщение о необходимости добавить прибор учета.

Второй важный сценарий — добавление устройства. Пользователь вводит серийный номер, выбирает найденный прибор и проходит подтверждение доступа к устройству . Если пароль указан верно, устройство добавляется пользователю и отображается на главном экране.

Также реализованы сценарии диагностики, просмотра информации об устройстве, передачи показаний и получения архива за выбранный период.
